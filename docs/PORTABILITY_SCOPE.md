# Framework portability scope

This file is the materialization manifest for the fresh local framework directory. It is
kept inside the new directory so the original project workspace needs no side-task report.

## Included

| Module | Included material | Reason |
|---|---|---|
| Rules | root `AGENTS.md`, architecture and operating docs | project-neutral authority and procedure |
| Harness | `kairos/kairos_harness/` Python, schemas, templates, tests, and docs | reusable context, graph, retrieval, promotion, and health implementation |
| Workshop | `workshop/src/runtime_sync_workshop/`, launcher, package metadata, neutral operator docs | reusable fail-closed synchronization machinery |
| Kickstart | `kickstart/`, project-intake schema, tests, and `docs/PROJECT_KICKSTART.md` | compiler-backed ground-truth discovery and exact initial source/header corpus binding |
| Database | `workspace/.kairos/kairos.db` generated by a fresh initializer | generic derived projection only; no inherited records |
| Dynamics | fresh workspace routers, events, receipts, and runtime state | generated from the new generic sources |
| Templates | document templates shipped by the harness and the neutral Workshop config template | safe project binding later |

## Excluded

The source tree, project reports and audits, customer or signal data, benchmarks, old
workspace documents, inherited SQLite files, runtime/blueprint corpus, transaction trees,
leases, seals, loop history, machine-specific configs, build fixtures, and installer patch
files are excluded. The untrusted initiation mockup is not a source or publication input; only the
compiler-backed initiation concept is implemented here. No file under the original project workspace was written.

## Sanitization and checks

The copied Workshop source uses configuration-derived source prefixes, neutral header
routing, generic dependent-test validation, and an optional parity adapter shell. Fixed
project counts and foreign symbol fixtures were removed from the new copy. A literal scan
over text sources is required to be empty for project names and path markers; Python
compilation, harness tests, workspace validation, health, and a question-oriented search
are the acceptance checks.

Remote publication is intentionally out of scope. Before a future GitHub action, produce a
new exact inclusion/exclusion list and obtain explicit approval.
